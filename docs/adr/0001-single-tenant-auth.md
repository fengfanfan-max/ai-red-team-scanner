# ADR-0001: v1 采用单租户认证，不做多租户

参考项目（VirtueRed）是商业化多租户 SaaS（独立 auth 服务 + 每表 tenant_id + RBAC）。本开源项目 v1 决定：一个部署实例 = 一个团队的工作空间，团队内多账号共享数据，无组织隔离；认证（注册/登录/改密码/JWT 过期）内置在 FastAPI 同一进程中，并提供 `AUTH_MODE=disabled` 免登录模式。

**Considered Options**

- 无认证：省事但失去全栈学习的关键环节（守卫/拦截器/中间件），且公开部署时任何人可消耗部署者的 LLM key。
- 多租户：每表 `tenant_id` + 租户开通/邀请流程 + 独立 auth 服务，横切复杂度会淹没 v1 其余部分的学习价值。

**Consequences**

- 未来迁移多租户需要全表加 tenant 维度 + 数据回填 + 引入 auth 服务，代价高——这是"难逆转"的部分，故立此 ADR 明确是**刻意取舍**而非遗漏。
- v1 所有登录用户权限等同，无角色体系；API key 加密与脱敏属于 v1 安全底线，不受此决策影响。
